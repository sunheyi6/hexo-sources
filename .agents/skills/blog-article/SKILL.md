# 博客文章写作（流殃风格）

以用户个人博客的写作风格产出中文文章。核心是"像聊天一样把一件事唠明白"，不是论文、不是营销文、不是技术文档。

## 文章骨架（Hexo 格式约定）

1. 文件名用标题本身，例如 `source/_posts/AI时代，开发者的竞争力到底是什么.md`
2. Front matter 放在最顶部：

```yaml
---
title: 文章标题
date: 2026-08-31 19:33:36（当前系统时间）
tags:
  - 标签1
  - 标签2
categories:
  - 分类（技术类常用 AI / 开发 / 其他）
description: 一句话摘要
---
```

3. Front matter 之后紧跟一句点题的话（类似"记录一下…""说说…"），然后空一行放 `<!-- more -->`，正文从分隔线之后开始
4. **不要手写 `abbrlink`**：hexo-abbrlink 插件在 `hexo generate` 时自动生成并写回
5. 写完文章不要自动 git 提交，等用户明确指示（见项目 AGENTS 约定）

## 写作风格

### 语气
- 全篇第一人称（我），自然带出"咱们""大家"这类词，像坐在对面聊天
- 口语词可以多用：说实话、说真的、其实、毕竟、那、唠唠、琢磨、瞎想
- 允许犹豫和自我暴露："我自己也有点不知道怎么做的感觉""说实话，这也是我最近的困惑"
- 避免照搬术语；用到术语必须立刻用大白话解释一遍，让非专家也能看懂

### 内容
- **以个人经历和真实感受为主**：写自己实际做过的事、踩过的坑、真实的想法变化，而不是空讲道理
- 多用具体例子/场景，把抽象观点落成"你平时会遇到的日常"
- 观点可以有倾向，但不说教、不喊口号；讲完留空间给读者自己判断

### 结构
- 中篇长度为主（几百到两千字常见），段落偏长但一段只讲一个意思
- 常用编号小节推进：第一/第二/第三，或第一步/第二步/第三步，标题口语化
- 并列要点用列表 + 加粗引导词：`- **关键词**：解释`
- 每篇文章结尾要有"收"的段落：要么总结自己的看法，要么向未来展望，要么抛个问题给读者——不要戛然而止

### 与 AI / 技术类内容结合时（可选加分项）
- 结合真实使用感受（用了什么工具、遇到什么问题、怎么解决的）
- 体现辩证思考：A 的好处 vs 局限，好的一面 vs 令人担心的一面
- 可以留一个开放问题，比如"以后会怎么样，需要时间和观察"

## 写作流程

1. 若用户只给了要点/提纲，先按要点列出文章结构给用户确认（标题、每节想讲什么）
2. 用户确认后，用 `write` 新建文件（含 front matter + 点题句 + `<!-- more -->`），正文骨架先写好或在确认后一次性写完
3. 需要改动时用 `edit` 做局部修改，不要整篇重写乱掉用户已有的内容
4. 写完后提示：可以 `hexo clean && hexo generate && hexo server` 本地预览（Git Bash 执行）；是否提交由用户决定

## 模板

```markdown
---
title: （标题）
date: （当前时间）
tags:
  - （标签）
categories:
  - （分类）
description:
---
（一句话点题，比如：记录一下……/聊聊……/来说说……）
<!-- more -->
（正文）
```
